# Agent configuration auto-sync design

## Goal

Make this repository the canonical desired configuration for Codex, Claude, and Copilot across machines. A new machine needs one bootstrap command after cloning; later local commits, branch switches, and pulls update the active configurations without requiring a setup command.

## Boundaries

Tracked configuration is portable and declarative: instructions, prompts, skills, generated agents, desired plugins, and tool settings. Runtime state remains machine-local: credentials, caches, trust decisions, desktop preferences, marketplace metadata, and tool-generated configuration. There is no local configuration overlay: remove `.codex/config.local.toml` and its example file.

Codex needs special treatment because its user-level `config.toml` contains both desired settings and runtime state. The committed Codex template must therefore not be the live file or a symlink to it.

## Design

Move the shared Codex template to a non-project-config location, such as `config/codex/global.toml`. Keep `.codex/config.toml` available only for Agent Kit project-specific settings, if any are needed.

Add one cross-platform Codex reconciliation command. It applies an explicit allowlist of managed settings from `config/codex/global.toml` into `~/.codex/config.toml`, removes settings that were previously managed but are no longer declared, and preserves every unmanaged setting. In particular, it preserves `projects`, `desktop`, `marketplaces`, tool-created MCP servers, authentication, caches, and any future unknown runtime keys. Trusted projects are runtime state, not a configurable overlay.

The existing direct links remain the mechanism for immutable surfaces and for tool configs whose runtime state is separate. Copilot's generated settings continue to use its shared/local layering, but are regenerated by the automatic sync path rather than only by a manually invoked link command.

Bootstrap configures Git to use this repository's tracked `.githooks` directory. `post-commit`, `post-merge`, and `post-checkout` invoke a lightweight, idempotent profile-sync command. Hooks must not block the Git operation: they report a clear warning on failure and exit successfully. The profile-sync command is also used by initial bootstrap and remains available for diagnosis or recovery.

## Data flow

1. `setup install` creates links, configures `core.hooksPath`, reconciles stateful config, and bootstraps plugins on a newly cloned machine.
2. A local commit that changes profile files runs `post-commit`, applying the desired configuration.
3. `git pull` runs `post-merge`, applying incoming profile changes.
4. A branch change runs `post-checkout`, applying that branch's profile.
5. Codex can continue writing its local state without modifying the repository.

## Safety and verification

The reconciler writes atomically and serializes concurrent runs. It creates a timestamped backup only before a material change. Tests cover managed additions, updates, deletions, unchanged no-op runs, and preservation of known and unknown runtime tables. Hook tests verify the hooks call the single profile-sync entry point and never fail a Git command.

## Non-goals

The design does not attempt to synchronize credentials, project trust, plugin caches, desktop preferences, or arbitrary tool runtime state. It does not depend on a filesystem watcher or a permanently running background service.
